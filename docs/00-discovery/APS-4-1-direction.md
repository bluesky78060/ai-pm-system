# APS-4-1: Discovery 자동 채움 — 방향 확정 문서

- **티켓**: APS-4-1
- **분류**: 1중 검증 (단순 가이드·템플릿 작성)
- **작성**: 메인 직접 (단축 정책)

## 1. 목표 (Why)

Discovery 단계에서 사용자가 7개 카테고리에 일일이 답변하는 시간을 줄이기. analyst 에이전트가 코드베이스 + 비슷한 과거 티켓 + 외부 docs를 자동 분석하여 답변 초안을 작성하면, 사용자는 검토·수정만 진행.

**성공 기준**: Discovery 사용자 응답 대기 -50% (수동 7개 답변 → 검토 1회).

## 2. 사용자 (Who)

- 메인 오케스트레이터 — analyst 호출 패턴 표준화
- analyst 에이전트 — 표준 prompt 받아 자동 채움 수행
- 사용자 — 답변 초안 검토만 (작성 부담 감소)

## 3. 범위 (What)

### 포함
- **`.claude/templates/discovery-auto-fill.md` 신설**: analyst 호출 표준 prompt 템플릿
  - 7개 카테고리별 자동 채움 가이드
  - 코드베이스·과거 티켓·docs 분석 지시
  - 출력 형식 (마크다운 7섹션)
  - 사용자 검토 체크리스트
- **`.claude/rules/discovery-and-plan.md` 보강**: 자동 채움 워크플로우 섹션 추가
  - 호출 순서: 티켓 발행 → analyst 자동 채움 → 사용자 검토 → 방향 확정
  - 자동 채움 적용 가능 조건
  - 자동 채움 생략 가능 케이스 (단순 변경)

### 제외
- analyst 에이전트 자체 코드 변경 (시스템 에이전트, 직접 수정 불가)
- 자동화 스크립트 (단순 가이드 + 템플릿)

## 4. 제약 (Constraints)

- analyst 에이전트는 oh-my-claudecode 플러그인 시스템 에이전트 → 호출 prompt만 표준화
- 마크다운 템플릿 (Claude Code가 직접 읽음)
- `.claude/templates/`, `.claude/rules/` 직접 편집 영역

## 5. 우선순위 (Priority)

- **P3** (사용자 응답 대기 시간 감소, 장기 누적 효과)

## 6. 리스크 (Risk)

| 리스크 | 영향 | 대응 |
|--------|------|------|
| 자동 답변 부정확 | 중 | 사용자 검토 단계 의무화, 수정 가이드 명시 |
| analyst 컨텍스트 폭주 | 저 | 분석 범위 제한 (관련 코드만, 최대 X개 파일) |
| 단순 변경에 과도 적용 | 저 | "생략 가능 케이스" 명시 |

## 7. 검증 (Verify)

### DoD
- `discovery-auto-fill.md` 템플릿 작성
- `discovery-and-plan.md`에 자동 채움 섹션 추가
- 사용자 검토 체크리스트 명시
- 적용 vs 생략 케이스 명확
